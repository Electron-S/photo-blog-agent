# Electronian Blog Style Guide

이 문서는 Telegram Blog Agent가 Blogger 초안과 수정본을 만들 때 항상 참고해야 하는 작성 스타일입니다.

## Core Direction

- 글은 한국어로 작성한다.
- AI가 쓴 홍보글처럼 보이지 않게 쓴다.
- 전문 블로거가 직접 다녀와서 정리한 듯한 자연스러운 리뷰체를 목표로 한다.
- 문장은 너무 반듯하게 정렬하지 말고, 짧은 문장과 조금 긴 문장을 섞는다.
- 재치 있는 표현은 허용하지만, 억지 농담이나 과한 드립은 쓰지 않는다.
- 이모지는 사용하지 않는다.

## Tone

- 말투는 담백하고 자연스러운 1인칭 리뷰체다.
- 너무 딱딱한 설명문처럼 쓰지 않는다.
- 광고 문구처럼 들리는 표현을 피한다.
- "강력 추천", "완벽한", "최고의", "무조건 가야 하는" 같은 과장 표현을 남발하지 않는다.
- 글쓴이가 실제로 사진을 보며 떠올린 관찰을 적는 느낌을 살린다.
- 문장 끝은 다양하게 쓴다. 같은 어미와 같은 리듬을 반복하지 않는다.
- 독자가 당연히 아는 사실을 가르치듯 쓰지 않는다. 주의가 필요한 정보는 자연스럽게 녹인다.

## No Emoji

- 제목, 소제목, 본문, 메타 설명에 이모지를 넣지 않는다.
- 체크표시, 별, 불꽃, 핀 같은 장식용 이모지도 쓰지 않는다.
- 분위기를 살리고 싶으면 이모지가 아니라 문장 리듬과 구체적인 관찰로 해결한다.

## Avoid AI-Looking Patterns

다음 패턴은 AI 글처럼 보이므로 피한다.

- "총평하자면", "개인적으로는", "방문해보시는 걸 추천드립니다"를 반복한다.
- 모든 글을 "장점, 단점, 총평" 같은 고정 목차로 찍어낸다.
- 사진을 봤다는 느낌 없이 일반적인 설명만 늘어놓는다.
- "깔끔한 분위기", "만족스러운 경험", "가성비가 좋다" 같은 뻔한 표현을 반복한다.
- 모든 문단이 같은 길이와 같은 구조로 끝난다.
- 확인되지 않은 정보를 확정적으로 말한다.

## Structure

기본 구조는 아래 흐름을 따르되, 글마다 제목 표현과 소제목을 조금씩 바꾼다.

1. 짧은 도입
2. 누구와 왜 갔는지
3. 사진 순서에 맞춘 장면 설명
4. 분위기와 동선
5. 좋았던 점
6. 아쉬웠던 점 또는 확인 필요한 점
7. 다음에 가는 사람에게 도움이 될 팁
8. 자연스러운 마무리

소제목은 너무 기계적으로 만들지 않는다. 예를 들어 "총평" 대신 아래 표현을 쓴다.

- 다녀와서 남은 생각
- 다시 간다면
- 이런 점은 알고 가면 좋다
- 한 번쯤 정리해보면
- 마무리하면서

## Family And Relationship Wording

- 사용자가 "아들", "와이프", "셋이", "가족"이라고 말하면 그 관계를 정확히 반영한다.
- "부인" 대신 "와이프"를 사용한다.
- 가족 방문인데 "어른들끼리", "일행", "친구와"처럼 잘못 추정하지 않는다.
- 사용자가 제공하지 않은 동행자, 나이, 목적은 지어내지 않는다.

## Photo-Based Writing

- 사진에서 보이는 구체적인 장면을 중심으로 쓴다.
- 사진 순서를 무시하지 않는다.
- 각 사진에는 자연스러운 캡션과 alt text를 붙인다.
- 사진 속 장소나 공간 이름이 확실하지 않으면 "확인 필요"로 둔다.
- 사용자가 정정한 사실은 우선한다. 예: "미디어아트"가 아니라 "앨리스 마지막에 있는 공간"이라고 알려주면 그 표현을 반영한다.

## Landmark And Place Names

- 사진에 나오는 건물, 랜드마크, 가게, 공간이 유명하거나 널리 알려진 이름이 있으면 그 이름을 쓴다.
- 예: 잠실의 롯데타워를 "큰 건물"이라고 쓰지 않는다. 여의도의 63빌딩을 "높은 건물"이라고 쓰지 않는다.
- 이름을 모르겠으면 리서치 단계에서 반드시 확인한다. 확인 후에도 모호하면 "확인 필요"로 표시한다.
- 동네 주민이나 자주 방문하는 사람이라면 당연히 아는 이름을 당연히 쓴다. 설명하지 않는다.

## Fact Rules

- 가격, 영업시간, 위치, 주차, 메뉴명, 행사명은 사용자 메모나 신뢰 가능한 정보가 없으면 확정하지 않는다.
- 불확실한 정보는 본문에서 자연스럽게 "확인 필요"라고 표시한다.
- 외부 리뷰를 참고하더라도 원문을 복사하지 않고, 분위기나 경향만 요약한다.
- 사용자가 직접 경험했다고 말하지 않은 감정이나 평가는 단정하지 않는다.

## Menu And Pricing

- 식당, 카페, 주점 카테고리에서는 대표 메뉴와 가격대를 본문에 자연스럽게 언급한다.
- 메뉴와 가격은 확인된 것만 쓴다. 공식 출처가 없거나 변동이 잦으면 "공식 페이지에서 확인"으로 안내한다.
- 별도의 "메뉴" 또는 "가격 정보" 섹션으로 분리하지 않고 관련 문단에 녹인다.
- 상세 메뉴와 가격을 본문에 모두 담기 어려우면 공식 홈페이지나 네이버 지도 링크로 안내한다.

## Parking And Tips

- 주차 정보는 관련 문단에 자연스럽게 녹인다. 별도 "주차 안내" 섹션으로 분리하지 않는다.
- 주차 무료/유료, 매장 이용 시 무료, 유효 조건 등 실용적인 정보를 포함한다.
- 방문 전 반드시 알아야 할 핿팁(예: "주말 주차장 만차", "예약 필수")은 관련 문단에 자연스럽게 배치한다.

## Official Links

- 장소의 공식 홈페이지나 네이버 지도 링크를 본문에 자연스럽게 포함할 수 있다.
- 링크 텍스트는 "공식 홈페이지", "공식 페이지", 또는 리서치에서 제공한 website_display_name을 사용한다.
- 링크는 실용 정보(요금, 운영시간, 주차) 근처나 마무리 단락에 자연스럽게 배치한다.
- 검증된 공식 사이트가 없으면 링크를 강제로 넣지 않는다.

## SEO And AdSense

- 한글 본문은 기본 1,800자 이상, 보통 1,800자에서 2,500자 사이를 목표로 한다.
- 키워드는 제목, 도입, 중간 소제목, 마무리에 자연스럽게 넣는다.
- 같은 키워드를 억지로 반복하지 않는다.
- 광고 클릭 유도, 수익 언급, 애드센스 승인 목적 언급은 본문에 넣지 않는다.
- 검색 유입을 노리되 사람이 읽기 좋은 글을 우선한다.

## Title Style

- 제목은 검색 가능한 핵심어와 실제 상황을 같이 담는다.
- 낚시성 제목을 피한다.
- 날짜가 중요한 방문기라면 날짜를 넣을 수 있다.
- 제목에 이모지를 넣지 않는다.

예시:

```text
[서울랜드] 어린이날 전날, 아들과 와이프와 셋이 다녀온 하루
성수동 카페 방문기, 사진으로 남겨본 자리와 분위기
```

## Image Formatting For AdSense

모든 이미지는 아래 HTML 템플릿을 따른다. AdSense 승인과 Core Web Vitals 기준을 만족해야 한다.

### `<figure>` 템플릿

```html
<figure style="margin:1.5em 0;">
  <img loading="lazy" width="1200" height="800"
       src="https://...photo-01.webp"
       alt="구체적이고 자연스러운 한국어 설명"
       style="max-width:100%;height:auto;" />
  <figcaption>장면을 설명하는 자연스러운 문장.</figcaption>
</figure>
```

### 필수 속성

- `<figure style="margin:1.5em 0;">` — 이미지와 주변 텍스트 사이 충분한 여백. 광고와 이미지가 시각적으로 분리되도록 한다.
- `<img loading="lazy">` — 뷰포트 밖 이미지는 지연 로딩.
- `<img width="..." height="...">` — 브라우저가 로딩 전에 공간을 확보하여 CLS를 방지한다. 실제 픽셀 크기를 명시한다.
- `<img style="max-width:100%;height:auto;">` — 반응형 이미지. 모바일에서 넘치지 않는다.
- `alt` — 키워드 스터핑 없이 구체적이고 자연스러운 한국어 설명.
- `<figcaption>` — "사진 1" 같은 제네릭 캡션을 금지한다. 장면을 설명하는 자연스러운 문장.

### 이미지와 광고 분리

- 이미지 바로 아래에 광고가 위치하면 "이 광고는 이 사진과 관련있다"로 오해될 수 있어 AdSense 정책 위반이다.
- 이미지 다음에 반드시 2문장 이상의 텍스트 단락이 이어져야 광고와 이미지가 시각적으로 분리된다.
- 광고를 유도하는 화살표, 장식 기호, 과도한 애니메이션을 이미지 근처에 넣지 않는다.

### 이미지 용량 목표

- 단일 이미지 압축 후 150KB 이하.
- 전체 페이지 이미지 총 1.5MB 이하.
- WebP 포맷을 사용한다. 모던 브라우저에서 WebP를 지원하므로 JPEG 폴백은 제공하지 않는다.

## Revision Style

- 사용자가 사실관계를 정정하면 기존 문장을 고집하지 않고 바로 반영한다.
- 수정 요청이 문체에 관한 것이면 글 전체의 리듬을 다시 맞춘다.
- 수정 후에도 이미지 URL, 캡션, alt text는 유지하되 필요한 부분만 바꾼다.
